## 浏览器真实操作

1. 游客在 Create 输入贪吃蛇指令，进入本地测试登录后保留输入，提交生成成功；刷新生成任务页仍显示服务端成功状态。
2. 进入私有预览，看到真实 iframe 的游戏画布及按钮。点击 START 后成为 RESTART，点击 PAUSE 后成为 RESUME，并显示 “Game paused.”；方向控制可点击。
3. 填写发布名称与说明、确认已试玩，发布成功。作品详情与 Home 中可见；点赞、评论和收藏提交成功，评论内容与计数可读取。
4. Home 进入沉浸游玩后仅保留退出按钮和底部导航，退出返回 Feed。Feed 已读取多项真实本地作品（最后一轮为 5 项）。
5. 从作品发起 Remix，页面显示来源与作者，提交生成成功；API 另以第二作者确认 parentId 和 originalCreator。
6. 网关重启后成员会话失效，作为访客打开另一作者公开链接，仍可真实 START→PAUSE，无需登录即可游玩。
7. 360px 创作页、430px 公开游玩和1280px 首页检查无横向溢出；桌面应用主体为480px。390px 已检查生成、预览、发布与沉浸游玩。
8. 无效公开链接不会加载 Artifact，显示不可用状态。全页导航后的新播放流程未新增控制台 JS 错误；之前开发 HMR 的 Context 错误已通过独立稳定 Context 模块修复。
9. 重新登录后收藏页仍显示此前收藏的两项作品；任务的验收结果弹层实际读取报告，显示验收等级与检查项，焦点落在关闭按钮。

## 修复的实际问题

- 原先私有 iframe 的入口能返回但脚本403；根因是沙箱 opaque origin 无法携带成员 Cookie。增加按 Artifact 授权的短期文件代理后，真实游戏按钮与画布可交互，且保持 `allow-scripts` 隔离。
- 开发热更新过程中 Context 导出变化导致 Member 读取 null；拆分稳定 Context 定义，重新加载后恢复生成任务。
- 多份本地开发服务共用默认 HMR 端口冲突；按 H5 端口派生 HMR 端口后双服务启动通过。
